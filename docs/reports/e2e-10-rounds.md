## บั๊กที่พบและแก้ไขแล้ว

### 1. `submit_answer` รับตัวเลือกที่ไม่มีอยู่จริง
- **อาการ:** ส่ง `choice = 9` ในข้อที่มี 4 ตัวเลือก ระบบยังบันทึกคำตอบลงตาราง `answers`
- **ผลกระทบ:** คะแนน/สถิติเพี้ยนได้ถ้ามีคนเรียก API ตรง ๆ หรือเบราว์เซอร์ค้างค่าเก่า
- **แก้ที่:** `supabase/migrations/0003_fix_answer_choice_range.sql` — ตรวจ `p_choice` อยู่ในช่วง `0 … จำนวนตัวเลือก-1` ไม่ใช่คืน `bad_choice`
- **ยืนยันหลังแก้:** `9 → bad_choice`, `-1 → bad_choice`, `null → bad_choice`, หมดเวลา → `time_up`

### 2. เปลี่ยนสถานะห้องย้อนกลับได้ (จบเกมแล้วกลับมาเล่นใหม่)
- **อาการ:** เรียก `host_set_status(room, 'lobby')` หลังเกมจบแล้วสำเร็จ ทำให้ห้องที่ `ended_at` ถูกตั้งแล้วกลับมาเปิดรับผู้เล่นอีกครั้ง
- **ผลกระทบ:** ข้อมูลรอบเก่าปนกับรอบใหม่ คะแนนค้าง กระดานสุดท้ายเพี้ยน
- **แก้ที่:** `supabase/migrations/0004_room_state_machine.sql` — บังคับลำดับสถานะ
  `lobby → question → reveal ⇄ leaderboard → ended` และ `ended` เป็นสถานะสุดท้ายถาวร
- **ยืนยันหลังแก้:** `ended → lobby` ได้ `bad_transition`, `lobby → leaderboard` ได้ `bad_transition`, สถานะใหม่ที่ไม่รู้จักได้ `bad_status`

### 3. เข้าห้องซ้ำด้วยชื่อเดิมช่วง lobby ไม่ได้
- **อาการ:** ผู้เล่นที่เข้าห้องแล้ว refresh/เปลี่ยนเครื่อง/เปิดสองแท็บ แล้วกรอกชื่อเดิม ได้ `nickname_taken` ทั้งที่เป็นตัวเขาเอง (ระหว่างเกมระบบจำได้อยู่แล้ว)
- **ผลกระทบ:** ผู้เล่นเข้าเกมไม่ได้ ต้องเปลี่ยนชื่อใหม่ ทำให้คะแนนแตกเป็นสองคน
- **แก้ที่:** `supabase/migrations/0005_rejoin_in_lobby.sql` — คืน `token` เดิม (rejoined = true) พร้อมอัปเดตตัวละคร แต่ยังกันคนอื่นสวมชื่อคนที่ตอบคำตอบไปแล้ว
- **ยืนยันหลังแก้:** เข้าซ้ำได้ token เดิม / ระหว่างเกมกลับเข้าได้ / คนใหม่เข้าเกมที่เริ่มแล้วยังถูกปฏิเสธ `game_started`

### 4. หน้าผู้เล่นแสดงจำนวนคนในห้องเป็น `undefined`
- **อาการ:** จอล็อบบี้ของผู้เล่นขึ้น “undefined คนในห้อง”
- **สาเหตุ:** อ่าน `st.player_count` จากตัวแปรสถานะผิดตัว
- **แก้ที่:** `docs/assets/js/page-play.js` — อ่านจาก `state.player_count`
- **ยืนยันหลังแก้:** แสดง “3 คนในห้อง” ถูกต้อง (มีเทสต์คุมใน `tools/e2e/run-pages.mjs`)

### 5. ตาราง `questions` ไม่มีข้อบังคับขั้นต่ำของตัวเลือก/ช่วงของเฉลย
บันทึกชุดคำถามที่มีตัวเลือก 1 ข้อ หรือ `correct_index` ชี้ไปนอกตัวเลือกได้ผ่าน API ตรง
→ หน้าเฉลยพังและคิดคะแนนไม่ได้
**แก้:** migration `0006` เพิ่ม `questions_options_len_chk` (2–6 ตัวเลือก),
`questions_correct_in_range_chk`, `questions_options_text_chk` (กันตัวเลือกว่าง) + index
(ทดสอบจริง: insert ที่ผิดถูกบล็อกทั้ง 4 แบบ, ข้อมูลเดิม 9/9 ข้อยังถูกต้อง)

### 6. นำเข้าคำถามที่มีตัวเลือกเกิน 6 ข้อ → เฉลยเลื่อนตำแหน่ง
แถวที่มี 7 ตัวเลือกถูกตัดเหลือ 6 เงียบ ๆ ทำให้ `correct_index` ชี้ผิดข้อ
(นำเข้าเฉลยข้อ 7 กลายเป็นข้อ 1)
**แก้:** ปฏิเสธแถวนั้นพร้อมเหตุผล “มี 7 ตัวเลือก เกิน 6 ข้อที่ระบบรองรับ”

### 7. นำเข้าคำถามที่เฉลยไม่ตรงกับตัวเลือก → ถูกปรับเป็น “ข้อ 1 ถูก” เงียบ ๆ
`resolveCorrect` เดิมคืนค่า 0 เมื่อหาคำตอบไม่เจอ = **ทำเครื่องหมายคำตอบผิดให้เป็นถูก**
**แก้:** คืน `-1` และข้ามแถวพร้อมแจ้ง “เฉลย "9" ไม่ตรงกับตัวเลือกที่มี”

### 8. ปุ่ม “เล่นชุดนี้อีกครั้ง” สร้างห้องใหม่ → ผู้เล่นทุกคนหลุดจากห้อง
ในห้องอบรมจริงทุกคนต้องสแกน QR ใหม่ (ปัญหาที่ผู้ใช้เจอหนักที่สุด)
**แก้:** เพิ่มปุ่ม “เริ่มรอบใหม่ในห้องเดิม” + ฟังก์ชัน `host_restart_room` (migration `0007`)
ล้างคะแนน/คำตอบแต่คงผู้เล่นและ PIN เดิม · ใช้ได้เฉพาะเจ้าของห้องและเฉพาะห้องที่จบแล้ว

### 9. ผู้เล่นค้างอยู่ที่จอ “จบเกม” ตลอดไปหลังเริ่มรอบใหม่
จอจบเกมสั่งปิด polling + realtime ทิ้ง (`stopAll`) → มือถือไม่รับรู้การเริ่มรอบใหม่เลย
และค่า `answeredQid`/`timerQid` ของรอบเก่าค้างอยู่ (คำถามชุดเดิม = id เดิม)
→ รอบใหม่ผู้เล่นถูกพาไปหน้าจอ “ตอบแล้ว” ทั้งที่ยังไม่ได้ตอบ
**แก้:** คงการเชื่อมต่อไว้ที่จอจบเกม + ล้างสถานะรอบเก่าเมื่อห้องกลับไป `lobby`

### 10. ตัวเลือก “แพ็กเพลง” ไม่มีผลกับเสียงจริง
เมนูตั้งค่าเพลง (ชิล / ตื่นเต้น / ไพเราะ) บันทึกค่าและแสดงผลถูกต้อง
แต่ `scheduleStep` เลือกเพลงจาก `musicWanted` (“lobby”) เท่านั้น
→ branch `gentle` เป็นโค้ดตาย ผู้ใช้เปลี่ยนแล้วไม่ได้ยินอะไรต่าง
**แก้:** ใช้ `cfg.pack` เมื่ออยู่ในโหมดห้องรอ + สลับแพ็กมีผลทันที

### 11. ไม่มีทางกลับเข้าห้องเดิมถ้าผู้ดำเนินรายการปิดแท็บกลางเกม
`API.myRooms()` มีอยู่แต่ **ไม่มีหน้าไหนเรียกใช้เลย**
**แก้:** หน้าจัดการชุดคำถามแสดงแผง “ห้องที่ยังไม่จบ” พร้อมปุ่มกลับเข้าห้องเดิม

### 12. ข้อความผิดพลาดจากฐานข้อมูลเป็นภาษาอังกฤษดิบ
**แก้:** `thaiDbError()` แปลง constraint / RLS / JWT / เครือข่าย เป็นภาษาไทยทุกจุด

## ทดสอบหน้าเว็บจริง (`tools/e2e/run-pages.mjs`)

โหลด HTML จริง + สคริปต์จริงทั้งหมดใน jsdom แล้วป้อนข้อมูลที่มีโครงสร้างตรงกับ payload จริงของ Supabase

### หน้าผู้จัด (`host.html`) — 30 ข้อ
เปิดห้อง, PIN + QR, การ์ดผู้เล่น, เอฟเฟคชื่อเด้งเมื่อมีคนเข้าห้อง, จอคำถาม, ตัวเลขผู้ตอบ + แถบความคืบหน้า,
นาฬิกา, จอเฉลย (ทำเครื่องหมายข้อถูก + แท่งสถิติ), คำอธิบายโหมดสัญลักษณ์, กระดานคะแนน,
ปุ่ม “ข้อต่อไป/จบเกม” เปลี่ยนตามข้อสุดท้าย, **บัลลังก์ผู้ชนะ + มงกุฎ + ตัวละคร 3 ตัว**, กระดานสุดท้าย

### หน้าผู้เล่น (`play.html`) — 22 ข้อ
เข้าห้อง, จำนวนคนในห้อง, ปุ่มตกแต่งตัวละคร, จอคำถาม 4 ตัวเลือก, นาฬิกา, กดตอบ → จอ “ตอบแล้ว” + คะแนน,
เฉลยถูก/ผิด, กระดานคะแนน + ไฮไลต์ตัวเอง, จบเกม (อันดับ 1 ได้บัลลังก์ / อันดับ 4 ไม่มีบัลลังก์),
token ใช้ไม่ได้ → หน้าข้อผิดพลาด, เข้าห้องซ้ำได้ token ใหม่, ชื่อซ้ำ → ข้อความไทย + ปุ่มกลับมากดได้,
หมดเวลา → ปุ่มตัวเลือกถูกล็อก

### หน้าผู้จัดชุดคำถาม (`admin.html`) — 14 ข้อ
สร้างชุดใหม่, เพิ่ม/ลบข้อ, กรอกโจทย์-ตัวเลือก-เฉลย, นำเข้าจาก CSV หัวตารางภาษาไทย,
แสดงตัวอย่างก่อนยืนยัน, CSV เสียไม่ทำให้พัง, ปุ่มเทมเพลท Excel, อ่านเทมเพลท `.xlsx` จริงได้ 5 ข้อ,

## กติกาการให้คะแนน (ตรวจจากฟังก์ชันจริงบนฐานข้อมูล)

```
คะแนนข้อนั้น = คะแนนเต็มของข้อ × (0.55 + 0.45 × เวลาที่เหลือ ÷ เวลาของข้อ)
ตอบผิด = 0 คะแนน
ตอบถูกติดกันตั้งแต่ 3 ข้อขึ้นไป = +100 คะแนนทุกข้อ
```

| ข้อละ 1,000 คะแนน (ให้เวลา 20 วิ) | คะแนน |
|---|---|
| ตอบทันที | 1,000 |
| ใช้ไป 5 วินาที | 888 |
| ใช้ไป 10 วินาที | 775 |
| ตอบวินาทีสุดท้าย (ถูก) | 550 |
| ตอบผิด | 0 |

แสดงกติกานี้ให้ผู้เล่นเห็นบนจอห้องรอแล้ว และอธิบายในคู่มือเทมเพลต Excel
